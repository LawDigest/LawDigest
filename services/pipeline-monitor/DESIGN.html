핵심 원칙

Pipeline Monitor는 운영 데이터를 다루지만, 시각적으로는 모두의입법의 하위 서비스여야 한다. 브랜드 문법은 유지하고, 정보 구조만 실행 로그와 산출물 중심으로 바꾼다.

브랜드 먼저

검정 wordmark와 레인보우 underline은 새 서비스에서도 첫 번째 신호다. 어드민 대시보드처럼 별도 브랜드를 만들지 않는다.

피드 문법 유지

최근 실행은 법안 피드처럼 읽힌다. 실행 ID보다 사람이 이해할 수 있는 요약 제목을 먼저 보여주고, 상세 정보는 chip과 footer로 정리한다.

운영 정확성

브랜드 감각을 유지하되 실패 원인, fallback 여부, 산출물 경로는 흐리지 않는다. 예쁜 카드보다 재현 가능한 로그가 우선이다.

브랜드 토큰

색상은 기존 `services/web/tailwind.config.js`와 `globals.css`에서 가져온다. 새 모니터링 앱은 이 토큰을 복제하거나 공유해야 한다.

구현 체크리스트

구현 에이전트는 새로운 시각 언어를 만들지 말고, 기존 모두의입법 웹의 토큰과 컴포넌트 습관을 모니터링 기능에 재사용해야 한다.

  • 1Pretendard와 Material Symbols를 기존 웹과 같은 방식으로 로드한다.
  • 2레인보우 그라디언트는 active tab, underline, 코드 패널 상단 라인에 사용한다.
  • 3primary CTA는 `bg-primary-3`, `text-white`, `rounded-full` 문법을 따른다.
  • 4최근 실행 목록은 법안 피드처럼 제목, 보조 제목, chip, footer 구조로 만든다.
  • 5모바일에서는 bottom floating nav를 유지하고, 데스크톱에서는 정보 밀도만 확장한다.
  • 6MVP는 읽기 전용이다. 실행, 재시도, 삭제 버튼은 디자인에 포함하지 않는다.
