Pipeline Monitor는 파이프라인을 꾸미기 위한 대시보드가 아니라, 실패 원인과 산출물 위치를 빠르게 확인하기 위한 운영 도구다. 이 디자인 시스템은 읽기 전용 모니터링 서비스가 어떤 밀도, 색상, 컴포넌트, 상태 표현을 가져야 하는지 정의한다.

문서 목적

이 문서는 실제 앱 구현 전에 사람과 에이전트가 같은 시각 방향을 공유하기 위한 기준점이다. 운영자가 첫 화면에서 봐야 하는 것은 멋진 차트가 아니라 마지막 성공 시각, 실패한 단계, fallback 발생 여부, 생성된 산출물이다.

MVP 범위: 이 서비스는 파이프라인 실행 로그와 산출물 메타데이터를 읽어서 보여준다. 실행, 재시도, 삭제 같은 쓰기 작업은 넣지 않는다. 운영 기능이 필요해지는 시점에는 별도 권한 모델과 감사 로그를 먼저 설계한다.

디자인 원칙

Pipeline Monitor의 화면은 시민 데이터 운영 도구답게 절제되어야 한다. 색과 장식은 의미를 보조하고, 표와 타임라인이 판단의 중심이 된다.

운영 판단 우선

최근 실행 상태, 실패 단계, 마지막 성공, 산출물 위치를 가장 먼저 보여준다. 사용자가 원인을 찾기 위해 여러 화면을 오가게 만들지 않는다.

조용한 밀도

대형 카드와 과한 여백을 줄이고, 표와 압축된 요약 영역을 통해 많은 실행 정보를 피로감 없이 비교할 수 있게 한다.

상태의 명시성

성공, 실패, 실행 중, 경고, 알 수 없음 상태는 색상만으로 표현하지 않는다. 모든 상태에는 한글 라벨과 보조 설명이 붙는다.

색상 토큰

배경은 밝은 중립색을 사용하고, 주요 동작과 선택 상태에는 낮은 채도의 녹색 계열을 사용한다. 실패와 경고는 작은 면적에서 강하게 보이도록 하고, 전체 화면이 한 가지 색조로 잠기지 않게 한다.

타이포그래피

본문 글꼴은 Pretendard와 시스템 산세리프를 우선한다. 실행 ID, 파일 경로, JSON, 로그는 모노스페이스로 고정해 비교 가능성을 높인다. 화면 안의 텍스트는 viewport width에 맞춰 임의로 커지거나 작아지지 않는다.

핵심 컴포넌트

컴포넌트는 실행 이력 탐색과 실패 원인 파악을 중심으로 구성한다. 읽기 전용 MVP에서는 실행 버튼보다 필터, 링크, 상세 로그, 산출물 확인이 더 중요하다.

Component 역할 구현 기준
SummaryStrip 마지막 성공, 마지막 실패, 실행 중, 처리 건수를 압축 표시 4개 이하 항목만 사용하고 숫자보다 운영 의미를 먼저 보여준다.
RunTable 실행 이력을 표로 비교 상태 열을 첫 번째에 두고, 오류는 한 줄 요약 후 상세로 연결한다.
StepTimeline 단계별 진행과 실패 위치 확인 각 단계에 상태, 시작 시각, 소요 시간, 오류 요약을 포함한다.
JsonBlock 구조화 로그와 결과 JSON 확인 pretty print, 가로 스크롤, 복사 동작을 지원한다.
ArtifactLink 실행 결과 파일 위치 확인 파일명, 형식, 크기, 생성 시각, 관련 실행 ID를 함께 표시한다.

상태 언어

상태 배지는 작지만 운영자가 가장 먼저 보는 정보다. 모든 배지는 한글 라벨을 포함하며, 색상은 빠른 스캔을 돕는 보조 신호로만 사용한다.

접근성과 구현 체크리스트

운영 콘솔은 빠르게 읽히는 만큼 정확하게 읽혀야 한다. 키보드 접근, 표 구조, 색상 대비, 상태 라벨은 구현 초기에 함께 잡아야 한다.

접근성 기준

  • 상태 배지는 색상 외에 한글 라벨을 항상 포함한다.
  • 표 헤더는 th와 scope를 사용해 관계를 명확히 한다.
  • 필터와 링크는 키보드 포커스 상태가 눈에 보여야 한다.
  • 로그와 JSON 블록은 마우스 없이도 선택과 복사가 가능해야 한다.

구현 기준

  • 첫 화면은 최근 실행 상태와 실패 원인을 먼저 보여준다.
  • 실제 집계 데이터 없이 차트나 장식성 KPI를 만들지 않는다.
  • 모바일에서도 표 비교가 가능하도록 가로 스크롤을 허용한다.
  • 읽기 전용 MVP에서는 실행, 재시도, 삭제 버튼을 제공하지 않는다.
