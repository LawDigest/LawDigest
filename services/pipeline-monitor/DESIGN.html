시스템 개요

이 디자인 시스템은 파이프라인 상태를 빠르게 판단하고, 실패 원인과 산출물까지 추적하는 운영 화면을 만들기 위한 기준이다.

Civic Ops Ledger

시민 서비스의 신뢰감과 운영 장부의 정밀함을 결합한다. 장식보다 판단 흐름을 우선한다.

Incident first

마지막 성공보다 현재 확인할 실패, fallback, 실행 중 상태가 먼저 보인다.

Reusable language

토큰, 컴포넌트, 상태 문구를 재사용해 다음 구현 화면에서도 같은 밀도와 미감을 유지한다.

디자인 토큰

기존 모두의입법 웹의 neutral-first 감각을 유지하되, 운영 도구에 맞게 검정 command surface와 작은 상태 색을 더한다.

타이포그래피

제목, 메타데이터, 로그가 서로 다른 임무를 갖도록 크기와 무게를 명확히 구분한다.

Pretendard + Fira Code
실패를 먼저 보고, 로그까지 바로 추적한다.

본문은 14-16px, 메타와 칩은 12px 이하로 내려가지 않는다. 숫자는 tabular figures로 맞추고, 로그와 artifact path는 mono로 읽힌다.

레이아웃 패턴

같은 데이터를 모바일과 데스크톱에 그대로 축소하지 않는다. 사용 맥락에 맞게 Pocket Ops와 Ledger + Trace로 나눈다.

Mobile: Pocket Ops

첫 화면에서 가장 중요한 상태 한 줄을 보여준다. 실패 원인과 trace 진입점이 함께 있어야 한다.

Filter rail

기간, 상태, provider, 검색은 34px 높이의 가로 rail로 둔다. full-width input stack은 금지한다.

Desktop: Ledger + Trace

실행 목록과 선택된 run의 trace를 동시에 본다. table, detail, log가 한 흐름으로 이어져야 한다.

컴포넌트 기준

각 컴포넌트는 모양보다 역할이 먼저다. 이름, 상태, 밀도, 상호작용이 구현 단계에서 흔들리지 않아야 한다.

OpsHeader

검정 command surface. 환경, 로그 경로, 갱신 상태가 들어간다.

IncidentStrip

모바일 첫 판단 단위. 문제와 trace 진입점을 같이 제공한다.

FilterRail

상태 확인 뒤 사용하는 보조 도구. 가로 스크롤 chip rail이다.

RunStack

모바일 실행 목록. row rhythm과 status marker로 읽힌다.

RunLedger

데스크톱 실행 테이블. selected row와 trace panel이 연결된다.

LogPanel

raw JSONL과 traceback을 확인하는 어두운 코드 표면이다.

접근성 및 검증 기준

디자인 시스템은 눈으로 보기 좋은 것에서 끝나지 않는다. 구현 전후로 대비, 포커스, 모바일 줄바꿈, 로그 가독성을 확인한다.

  • 1본문 대비는 WCAG AA를 통과한다. 작은 텍스트는 #707070 이상으로 유지한다.
  • 2아이콘 단독 버튼에는 aria-label을 둔다. 포커스 상태는 눈에 보여야 한다.
  • 3상태는 색만으로 구분하지 않는다. 성공, 실패, 실행 중 같은 텍스트 라벨을 함께 쓴다.
  • 4390px 모바일 캡처에서 제목, incident, filter rail이 화면 밖으로 밀리지 않아야 한다.
  • 5로그와 artifact path는 선택 가능한 텍스트로 남긴다. 이미지화하지 않는다.
  • 6레인보우는 상단 hairline과 wordmark underline 외에 사용하지 않는다.
