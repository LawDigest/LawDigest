브랜드 토큰은 같게, 모니터링 UX는 별도로

Pipeline Monitor는 모두의입법의 폰트, 컬러, 버튼 감각을 사용하지만 시민용 피드 화면을 복제하지 않는다. 이 문서는 파이프라인 운영자가 최근 실행, 실패 단계, fallback, 산출물, 원시 로그를 빠르게 확인할 수 있는 table-first 모니터링 UI를 정의한다.

유지 Pretendard, #191919, gray scale, #96BCFA, #E63946
변경 피드형 UI가 아니라 실행 테이블과 로그 중심 운영 화면
제한 레인보우는 wordmark underline과 문서 예시에만 사용
토큰 레인보우 사용 모니터링 화면 컴포넌트 상태 언어 구현 체크리스트

브랜드 토큰

색상과 폰트는 모두의입법 웹에서 가져온다. 다만 토큰을 가져온다는 것은 기존 화면 구조까지 가져온다는 뜻이 아니다. 운영 화면에서는 정보 밀도와 오류 추적성이 우선이다.

레인보우 사용 원칙

레인보우 그라디언트는 모두의입법의 브랜드 서명이다. 모니터링 화면에서는 눈에 띄는 장식이 아니라, 이 서비스가 모두의입법 계열이라는 최소한의 단서로만 사용한다.

허용

상단 2px 라인, wordmark underline, 브랜드 토큰 설명의 단일 예시. 한 화면에 1-2회 정도만 등장한다.

금지

gradient button, gradient pill, gradient chart, 코드 패널 상단 반복 라인, 상태색을 rainbow stop으로 매핑하는 방식.

모니터링 화면 구조

컴포넌트 기준

핵심 컴포넌트는 운영자가 실행 이력을 비교하고 오류를 추적하는 순서로 설계한다. 장식용 컴포넌트보다 상태, 필터, 표, 상세, 로그가 우선이다.

SystemHeader 브랜드와 환경, 마지막 갱신 시각 표시 wordmark 아래에만 얇은 레인보우 underline 사용
ControlToolbar 기간, 상태, command, 검색, refresh 제어 48-56px 높이의 단단한 toolbar
HealthStrip 마지막 성공/실패, 실행 중, fallback 요약 4개 이하 항목, 텍스트 우선
RunTable 최근 실행 비교와 필터링의 중심 상태, 시작, command, provider, 오류, 산출물 열 필수
RunDetailPanel 선택한 run의 metadata, step, artifacts 확인 desktop right panel, mobile single column
LogPanel JSONL 원문과 traceback 확인 dark-b 배경, mono, 가로 스크롤

상태 언어

상태는 색상만으로 전달하지 않는다. 모든 상태는 작은 badge와 한글 라벨, 필요 시 오류 요약을 함께 제공한다.

성공 / 실행 중

성공은 산출물 생성 여부를 함께 보여준다. 실행 중은 시작 시각과 경과 시간을 반드시 포함한다.

실패 / fallback

실패는 실패 단계와 오류 첫 줄을 보여준다. fallback은 대체 provider와 원인을 표시한다.

구현 체크리스트

실제 구현 단계에서는 아래 기준을 만족해야 한다. 특히 레인보우 사용량과 read-only 범위를 유지하는 것이 중요하다.

  • 1Pretendard, Material Symbols, 모두의입법 색상 토큰을 동일하게 적용한다.
  • 2레인보우는 상단 브랜드 라인과 wordmark underline 정도로 제한한다.
  • 3첫 화면은 HealthStrip, ControlToolbar, RunTable, RunDetailPanel로 구성한다.
  • 4LogPanel은 dark-b, mono, raw/pretty view를 제공한다.
  • 5MVP에는 실행, 재시도, 삭제, 롤백 버튼을 넣지 않는다.
  • 6실제 집계 데이터 없는 차트와 장식용 gradient UI를 만들지 않는다.
