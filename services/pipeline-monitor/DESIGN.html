파이프라인 상태를 읽는 command ledger

브랜드 토큰은 모두의입법과 같게 둔다. 화면은 다르게 설계한다. 이 문서는 실행 테이블, trace stack, raw log를 중심으로 한 데이터 파이프라인 모니터링 UI를 정의한다. 더 강한 인상은 gradient가 아니라 검정 command surface와 ruled ledger 구조에서 나온다.

Extract 결과

기존 웹에서 가져오는 것은 브랜드 재료다. 시민용 피드, 모바일 floating nav, 검색 진입점의 UX를 그대로 옮기지 않는다.

Typography

Pretendard 하나로 한글 UI 계층을 만든다. run id, path, JSON key는 mono로 전환한다.

Color

중립 흰색/회색, #191919 ink, #96BCFA focus/info, #E63946 failure를 그대로 사용한다.

Surface

flat by default. 정보 패널은 shadow보다 1px ruled border와 밀도 있는 spacing으로 구분한다.

Rainbow

브랜드 hairline과 wordmark underline으로만 남긴다. 버튼, 차트, 상태에는 쓰지 않는다.

Buttons

검정 primary와 회색 secondary는 유지하되, 운영 도구에서는 radius 8px 기본값을 사용한다.

States

성공, 실패, 실행 중, fallback, 알 수 없음은 색상과 텍스트 라벨을 함께 사용한다.

토큰

대비를 위해 작은 텍스트는 기존 muted보다 진한 값을 사용한다. `#999999`는 보조 메타 이상으로만 제한한다.

Shape brief

물리적 장면은 밝은 작업 환경에서 배포 직후 상태를 빠르게 확인하는 운영자다. 그래서 light surface를 유지하고, command 영역만 검정으로 단단하게 잡는다.

Primary action 이상 run을 선택한다. 오른쪽 trace stack에서 실패 단계와 raw log를 확인한다.
Layout 상단 command bar, compact toolbar, left ledger table, right trace stack. 하단 raw log panel은 필요할 때 확장한다.
Visual lane GitHub Actions의 추적성, Linear table의 밀도, Raycast settings의 단단한 컨트롤. 브랜드성은 색과 폰트로만 연결한다.

컴포넌트

구현은 아래 컴포넌트를 먼저 잡는다. 이 순서가 곧 사용자 판단 순서다.

CommandBar환경, 로그 경로, 갱신 상태를 담는 검정 command surface.Rainbow는 wordmark underline에만 사용한다.
HealthLedger마지막 성공, 마지막 실패, 실행 중, fallback을 한 줄로 표시.KPI 카드 그리드 대신 ledger row로 구성한다.
RunLedgerTable최근 실행 비교의 중심 컴포넌트.선택 row는 paper-blue 배경으로만 표시한다.
TraceStack선택 run의 metadata, step, artifact, error를 오른쪽에서 추적.Step marker는 작은 square로 유지한다.
LogPanelJSONL 원문과 traceback을 확인하는 dark panel.Gradient top border 없이 mono와 대비로 구분한다.

구현 체크리스트

`bolder`의 결과는 더 강한 위계이지 더 많은 효과가 아니다. 검증 기준도 그에 맞춰 둔다.

  • 1모두의입법 토큰과 Pretendard를 사용한다.
  • 2첫 화면은 command bar, ledger table, trace stack으로 구성한다.
  • 3레인보우는 브랜드 hairline과 wordmark underline으로 제한한다.
  • 4모든 작은 텍스트는 WCAG AA 대비를 확인한다.
  • 5MVP에는 실행, 재시도, 삭제, 롤백 버튼을 넣지 않는다.
  • 6실제 집계 없는 차트와 장식용 gradient UI를 만들지 않는다.
