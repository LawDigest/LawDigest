# 법안 제목 전용 재생성 설계

## 목표

에이전트형 Markdown 리포트가 이미 있지만 `title`이 원문 `summary` 앞부분을 복사한 법안만 찾아, 리포트 본문을 다시 생성하지 않고 제목만 에이전트가 생성하도록 한다. 첫 운영 실행은 최신 대상 5건으로 제한한다.

## 대상 계약

다음 조건을 모두 만족하는 행만 대상이다.

- `gpt_summary`에 `## 쉬운 요약`과 `## 주요 내용`이 모두 있다.
- `title`과 `summary`가 비어 있지 않다.
- 공백을 하나로 정규화한 `summary`에서 선두의 `제안이유 및 주요내용`을 제거한다.
- 현재 `title`에서 끝의 공백, 마침표, 말줄임표를 제거한 문자열이 위 `summary` 본문의 prefix와 일치한다.

운영 DB에서 이 조건은 2026-07-16 조사 시점에 3,539건이다. 실행 시점에는 조건을 다시 평가하며 `propose_date DESC, bill_id DESC` 순서로 `limit`만큼 선택한다.

## 생성 경로

별도 제목 전용 프롬프트에 `bill_id`, 정확한 `bill_name`, 원문 `summary`, 기존 `gpt_summary`를 제공한다. 에이전트는 JSON의 `title`만 반환한다. 제목은 기존 `_validate_generated_title`로 검증하고, 원문이나 리포트의 첫 문장을 그대로 복사하지 못하게 프롬프트에 명시한다.

한 요청은 최대 5건을 처리한다. 전체 리포트 생성에 쓰는 evidence 수집, Markdown 생성, 툴팁 처리와 리포트 검증은 실행하지 않는다.

## 저장 안전장치

저장은 `UPDATE Bill SET title = ... WHERE bill_id = ... AND title = <조회 당시 값>` 형태의 낙관적 조건부 업데이트로 수행한다. 따라서 조회 후 다른 작업이 제목을 바꿨다면 덮어쓰지 않고 실패로 기록한다. `gpt_summary`, `summary_tags`, `category`를 SQL의 `SET` 절에 포함하지 않는다.

`dry_run`은 대상 선정과 제목 생성·검증 및 결과 파일 작성까지만 하고 DB를 수정하지 않는다. `prod` 실행 뒤에는 대상 5건의 제목 계약과 `gpt_summary` SHA-256이 실행 전과 같은지 확인한다.

## 실패 처리와 결과

JSON 파싱 실패, 누락, 중복 `bill_id`, 제목 계약 위반은 저장 전에 실패시킨다. 결과 JSON에는 대상 수, 성공·실패 수, 각 법안의 이전 제목과 새 제목, DB 반영 여부와 오류를 남긴다. 첫 5건 중 일부만 성공하면 성공한 제목만 반영하고 실패 항목은 명시적으로 보고한다.

## 범위 밖

- 기존 `gpt_summary` 또는 리포트 Markdown 재생성
- 3,539건 전체 운영 실행
- 나머지 681건 또는 레거시 제목 정리
- 제목 형식 계약 변경
