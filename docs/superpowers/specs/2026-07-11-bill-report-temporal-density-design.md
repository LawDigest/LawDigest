# 법안 리포트 시점 및 분량 검증 설계

> Superseded: 시점 confidence와 본문 정규식 게이트는 `2026-07-11-bill-report-prompt-only-temporal-design.md`의 프롬프트 기반 출처 구분으로 대체됐다. 분량 계약만 유지한다.

## 목표

법안 발의 당시의 법령 설명과 리포트 생성 시점의 최신 시행 조문을 구분하고, 법안의 실제 변경 복잡도에 맞는 길이로 리포트를 생성한다.

## 현재 문제

`bill_text.proposal_reason_and_major_content`는 발의 당시의 `현행법`을 설명하지만, `current_law`는 생성 시점에 법제처에서 조회한 최신 조문이다. 통과·공포된 법안은 최신 조문에 개정 내용이 이미 반영될 수 있어 두 근거를 같은 시점으로 읽으면 개정 전후가 뒤섞인다.

모든 법안을 `deep_report`로 처리하면서 `무엇이 달라지나`를 가능하면 4~6개로 나누도록 요구하고 있어, 단일 조문·단일 변경 법안도 효과와 집행 쟁점을 별도 변경처럼 반복할 수 있다.

## 설계

### 시점 계약

evidence packet에 다음 메타데이터를 추가한다.

- `temporal_context.proposal_baseline`: 발의 당시 법령 설명의 경로와 법안 발의일
- `temporal_context.current_law_snapshot`: 최신 시행 조문의 조회 상태, 경로, 조회 기준일. 실제 조문을 찾았을 때만 `status=found`와 기준일을 기록한다.
- `temporal_context.passed`: 통과·공포 법안 여부

에이전트 출력에는 `temporal_consistency` 객체를 추가한다.

```json
{
  "report_body": "# 법안명\n...",
  "temporal_consistency": {
    "confidence": "high",
    "reason": "발의 당시 기준과 현재 시행 조문을 구분했습니다."
  }
}
```

코드는 `confidence=high`인 structured output만 통과시킨다. raw Markdown은 실패한다. 통과 법안 본문에서 `현행법`, `현행 조문`을 시점 수식 없이 사용하면 실패한다. `발의 당시 현행법`, `개정 전 조문`, `현재 시행 조문`처럼 기준이 명시된 표현은 허용한다. 최신 시행 조문을 찾지 못했으면 현재 법령 상태를 주장할 수 없다.

### 분량 계약

evidence packet의 조문 참조 수와 제안 이유 길이로 리포트 밀도를 나눈다.

- `simple`: 조문 참조가 1개 이하이고 제안 이유가 1,500자 이하
  - 변화 묶음 2~3개
  - 목표 2,200~3,200자
  - 최대 3,600자
- `complex`: 그 밖의 법안
  - 변화 묶음 4~6개
  - 목표 3,500~5,500자
  - 최대 6,500자

최대 길이나 변화 묶음 수를 넘으면 검증 실패로 처리한다. 생성된 Markdown을 잘라내지 않는다. 기존 실패 재시도 경로가 해당 법안만 다시 생성한다.

### 검증과 재시도

시점 판정 누락, 낮은 confidence, 무자격 시점 표현, 분량 초과는 모두 `validation` 실패로 분류한다. 기존 `failure_retry_attempts`가 설정된 실행은 단건 재시도를 수행한다. DB upsert는 모든 검증을 통과한 뒤에만 실행한다.

## 범위 제외

- DB 스키마와 저장 컬럼은 변경하지 않는다.
- 법률용어 툴팁 파이프라인은 변경하지 않는다.
- 별도 모델 QA 턴을 추가하지 않는다.
- 리포트 본문을 사후 절단하거나 요약하지 않는다.

## 성공 기준

- 보건의료기술 예시처럼 발의 당시 설명과 최신 시행 조문이 다른 경우 시점이 구분된다.
- 단일 변경 법안은 변화 묶음이 3개를 넘지 않고 3,600자를 넘지 않는다.
- 복합 법안은 기존 정보 밀도를 유지한다.
- 검증 실패 리포트는 DB에 반영되지 않고 기존 단건 재시도 대상으로 분류된다.
- Luna 단건 dry-run smoke가 structured output, 시점 gate, 분량 gate, 기존 QA를 모두 통과한다.
